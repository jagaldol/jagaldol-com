**개인 기록을 AI의 작업 맥락으로 만드는, Obsidian 기반 AI 개인비서 하네스입니다.** 일정·할 일·지식을 하나의 워크스페이스에 연결하고, AI가 이를 읽고 갱신할 수 있도록 지침과 작업 절차를 설계했습니다.

개인용으로 사용하던 시스템을 다른 사람도 설치하고 계속 고쳐 쓸 수 있는 제품으로 확장했습니다. **Vault 구성부터 CLI, 사용자 변경을 보존하는 업데이트 엔진, 라이선스 서비스와 배포까지 개발해 첫 유료 판매로 연결했습니다.**

[Lifebase 웹사이트](https://lifebaseai.com/) · [설치 CLI](https://www.npmjs.com/package/@lifebase/cli)

## 개발 배경

AI에게 오늘의 일정을 계획해 달라고 하려면, 진행 중인 일과 지난 기록, 생활 패턴을 함께 알려줘야 합니다. 대화가 바뀔 때마다 이 맥락을 다시 전달하고, 결과를 따로 정리하는 과정이 반복됐습니다.

이를 줄이기 위해 **사람이 읽고 관리하는 개인 기록을 AI도 직접 작업하는 공간**으로 만들었습니다. Obsidian의 Markdown 파일을 중심에 두고, 무엇을 참고하고 어떤 형식으로 기록할지 정의했습니다. 대화의 결과가 일정·할 일·지식 노트에 남아 다음 작업의 맥락으로 이어지도록 구성했습니다.

## 개인 기록 위에서 동작하는 하네스

`AGENTS.md`는 공통 행동 규칙과 작업의 진입점을 안내합니다. 상세 절차는 작업별 문서와 스킬로 나누어, 모든 지침을 한 번에 전달하지 않고 필요한 내용을 찾아 적용하도록 했습니다.

전체 16개 스킬 가운데 **`lifebase`는 공통 작업 지침**, **`lifebase-note-writing`은 노트 작성의 품질 기준**을 담당합니다. 그 위에 일정 계획·하루 마감·Task 관리와 워크스페이스 정비, 업데이트·백업 절차를 구성했습니다.

예를 들어 일정을 계획할 때는 사용자 선호와 기존 일정, 진행 중인 Task를 참조하고 일간 노트에 계획을 작성합니다. 이후 사람이 Obsidian에서 수정한 내용도 같은 기록에 남습니다. 노트의 속성·위키링크·템플릿을 맞춰, 다음 작업에서 다시 찾아 활용할 수 있도록 했습니다.

## 가장 어려웠던 문제: 사용자가 고친 제품을 업데이트하기

배포 후에는 사용자마다 노트와 설정, AI 지침이 달라집니다. 새 버전의 파일로 덮어쓰면 개인화한 내용을 잃고, 기존 파일을 모두 유지하면 제품 개선을 전달할 수 없습니다.

이를 해결하기 위해 **이전 배포본(Base), 현재 사용자 파일(Local), 새 배포본(Target)을 비교하는 업데이트 엔진**을 만들었습니다. 제품의 변경과 사용자의 변경을 구분하고, 충돌이 있는 파일은 AI 검토를 거쳐 처리하도록 했습니다.

**AI는 변경의 의미를 검토하고, CLI는 검증된 결정을 파일에 반영하도록 역할을 나눴습니다.** AI가 병합 초안을 만들었다는 이유만으로 적용하지 않습니다. 기존 파일 유지·새 버전 사용·병합 결과 사용 중 처리 결정을 명시해야 하며, 미해결 항목이 남으면 업데이트를 완료하지 않습니다.

파일마다 소유권도 구분했습니다. 버전 정보 같은 배포 메타데이터는 새 릴리스에 맞추되, 개인 노트는 검토 없이 교체하지 않습니다. 최종 반영 전에는 파일 상태를 다시 확인하고 복구용 백업을 마련해, 검토 이후 변경된 파일까지 그대로 덮어쓰지 않도록 했습니다.

## 업데이트를 사용자에게 전달하는 CLI

업데이트 엔진을 실제 사용 흐름으로 연결하기 위해 **TypeScript 기반 Lifebase CLI를 개발하고 npm 패키지로 배포했습니다.** 사용자가 배포 파일을 찾아 내려받거나 교체할 파일을 직접 판단하지 않아도, 현재 설치 상태에서 이용 가능한 버전을 확인하고 업데이트를 시작할 수 있도록 했습니다.

`lifebase`를 실행하면 현재 Vault 버전과 라이선스 상태를 보여주고, 메뉴에서 업데이트와 에이전트 연결을 선택할 수 있습니다. 처음 사용하는 경우에는 인증·언어·버전·설치 위치 선택을 순서대로 안내합니다. 업데이트 중 검토가 필요하면 AI 에이전트가 이어서 처리할 수 있도록 검토 공간과 후속 작업을 준비합니다.

**사람에게는 대화형 메뉴를, AI와 자동화에는 명령과 JSON 출력을 제공합니다.** 두 인터페이스가 같은 업데이트 엔진을 사용하도록 구성해, 에이전트가 파일 반영 절차를 매번 새로 구현할 필요를 줄였습니다. macOS·Windows·Linux에서 같은 npm 패키지로 설치할 수 있습니다.

[npm 패키지](https://www.npmjs.com/package/@lifebase/cli) · [설치 가이드](https://lifebaseai.com/docs/getting-started/install/) · [CLI 문서](https://lifebaseai.com/docs/cli/)

Cloudflare Workers에 라이선스 API를 구현하고, D1에서 계정·이용 권한·설치 기기를 관리합니다. 비공개 GitHub Release의 배포 파일은 이용 권한을 확인한 뒤 전달합니다. 이메일 발송은 Queue로 분리하고, 메일 원문과 첨부는 R2에 보관합니다. 웹사이트와 관리자 화면을 통해 제품 안내와 라이선스 발급·운영을 연결했습니다.

**라이선스 서버는 이용 권한과 배포 파일 전달을 담당하고, 노트 내용·로컬 diff·병합 결과는 받지 않습니다.** 개인 파일의 비교와 업데이트는 사용자 기기에서 수행하도록 경계를 정했습니다.

## 검증과 운영

개인 프로젝트로 하네스 설계, CLI·서버·웹 구현과 릴리스 운영을 맡았습니다. 기록 탐색과 편집에는 Obsidian 및 기존 플러그인을 활용하고, 직접 개발한 범위는 작업 지침과 스킬, 배포·업데이트·라이선스 시스템에 집중했습니다.

릴리스에서는 ZIP 내부 경로와 파일 해시, 필수 설정, 언어별 링크를 검증합니다. CLI는 macOS·Windows·Linux에서 테스트하고, CLI와 라이선스 서버의 연동도 통합 테스트로 확인합니다. Vault 제품과 npm CLI는 버전을 분리해 각각 배포합니다.

2026년 9월 10일 **첫 유료 판매를 완료했습니다.** 현재는 결제 확인 후 관리자 화면에서 라이선스를 발급하는 방식으로 운영하고 있으며, 자동 결제 연동은 후속 범위로 남겨두었습니다.
