# 슬라이드 포트폴리오

`/portfolio`는 `next.config.ts`의 rewrite로 `index.html`을 제공한다. 사이트의 공통 헤더·푸터와 CSS를 적용하지 않고 원본 1920×1080 슬라이드 디자인을 유지한다. 서버에서 PDF를 생성하거나 개인정보를 전송하지 않는다.

- `index.html`: 12페이지의 원본 문구, 링크, 이미지 배치. 내용을 변경할 때 이 파일을 수정한다.
- `deck.css`: 슬라이드·인쇄·전체 화면 스타일과 기본 WOFF2 폰트. `extra-fonts.css`는 편집 시 필요한 추가 글자 폰트다.
- `controller.js`: 페이지 이동, 전체 화면, 로컬 문구 편집, 저장.
- `assets.js`: 화면별 이미지 활성화와 PDF/HTML 저장용 리소스 포함 처리.
- `pdf.js`: 브라우저에서 이미지 기반 16:9 PDF를 생성하고 링크를 보존한다. 글자 선택·검색은 지원하지 않는다.
- `assets/`: 원본 PPT에서 추출한 이미지의 WebP/SVG와 WOFF2 폰트. 파일명은 내용 해시이며 장기 캐시를 사용한다. 교체할 때 새 파일명을 사용하고 참조도 갱신한다.

폰트는 현재 문구·기본 기호의 작은 묶음과 나머지 글자 묶음으로 나누고 `unicode-range`로 선택한다. 추가 묶음의 스타일시트는 기본 문구에 없는 글자를 편집할 때만 활성화한다. 편집으로 새로운 글자가 추가되어도 폰트가 지원하는 글자라면 나머지 묶음을 받아 표시한다. 이미지에는 첫 슬라이드를 제외하고 `data-src` 또는 `data-href`를 사용한다. 슬라이드를 열면 실제 주소를 설정한다.

PDF 저장은 방문하지 않은 페이지까지 모든 이미지와 폰트를 가져와 변환용 사본 안에 포함한다. 원격 자료를 받지 못하면 오류를 알리며 불완전한 파일을 다운로드하지 않는다. 편집 후 HTML 저장도 모든 자료를 포함한 오프라인 파일로 내려받는다. 편집 내용은 해당 브라우저의 localStorage에 저장되며 공개 원문을 바꾸지 않는다.

## 확인

`npm run dev` 후 `/portfolio`에서 확인한다. `npm run lint`와 `npm run build`를 실행한다. Playwright가 있는 환경에서는 다음 브라우저 검증도 사용할 수 있다. 프로젝트 런타임 의존성을 추가할 필요는 없다.

```sh
PORTFOLIO_URL=http://localhost:3000/portfolio node scripts/check-portfolio.mjs
```

별도로 설치된 Playwright는 `PLAYWRIGHT_MODULE`에 모듈 경로를, Chrome은 `CHROME_PATH`에 실행 파일 경로를 지정한다. 검증은 초기 전송량, 지연 로딩, 전체 화면, 문구 보존, 직접 PDF 다운로드, 오프라인 HTML 저장을 확인하고 임시 폴더에 PDF와 화면 캡처를 남긴다. PDF의 페이지 수·문구 배치·이미지와 링크는 결과 파일로 확인한다.

원본 보관본은 Lifebase의 `2026-09-17-portfolio.html`이며 이 디렉터리가 웹 공개용 소스다. 기존 사이트 내비게이션 변경이나 배포는 별도 작업이다.
